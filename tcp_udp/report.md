# Краткие итоги: Транспортный уровень (TCP и UDP)

1. Транспортный уровень обеспечивает прямую связь и передачу данных между приложениями на разных хостах.
2. Для адресации приложений на транспортном уровне используются порты в диапазоне от 1 до 65535, образующие вместе с IP-адресом сокет.
3. Хорошо известные порты (1–1024) зарезервированы для базовых служб, таких как HTTP (80), DNS (53) и DHCP (67–68).
4. Динамические и частные порты (49152–65535) операционная система автоматически назначает клиентским приложениям.
5. Протокол UDP (User Datagram Protocol) является ненадежным протоколом без установления соединения, обеспечивающим высокую скорость передачи за счет отсутствия подтверждений и контроля потока.
6. UDP применяется в задачах с короткими запросами и ответами, например, в службах DNS, DHCP и SNMP.
7. Протокол TCP (Transmission Control Protocol) гарантирует надежную доставку потока байт с сохранением правильного порядка следования сегментов.
8. Установление соединения в TCP выполняется с помощью трехкратного рукопожатия (3-way handshake: SYN, SYN-ACK, ACK).
9. TCP поддерживает механизм управления потоком и перегрузкой сети с помощью динамического изменения размера окна и подтверждений (ACK).
10. Для завершения TCP-соединения используется процедура с обменном флагами FIN и ACK, обеспечивающая корректное закрытие сеанса.
