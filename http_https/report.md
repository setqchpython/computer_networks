# HTTP: основы, разбор запросов и ответов

## 1. Определения терминов

1. **HTTP (HyperText Transfer Protocol)** — сетевой протокол прикладного уровня, обеспечивающий взаимодействие веб-браузера с сервером. Применяется для отправки запросов и получения различных веб-ресурсов (документов, мультимедиа, текстов) по классической архитектуре «запрос — ответ».

2. **HTTPS** — защищенная вариация протокола HTTP, задействующая алгоритмы шифрования данных. Обеспечивает конфиденциальность информации, подтверждает подлинность веб-ресурса с помощью сертификатов и предотвращает перехват или модификацию трафика злоумышленниками. Функционирует поверх портов 443 (в отличие от HTTP, использующего порт 80).

3. **Клиент-серверная модель** — архитектурный паттерн, при котором клиентская часть (например, браузер или специализированный софт) инициирует запрос, а серверная сторона принимает его, выполняет обработку и отправляет обратно сформированный ответ. Один сервер способен параллельно обслуживать множество клиентских подключений.

4. **Идемпотентность** — свойство метода, при котором многократное отправление идентичного запроса приводит к абсолютно одинаковому состоянию системы, аналогичному однократному выполнению. Так, многократная команда на удаление конкретного файла приведет к его уничтожению лишь при первом вызове. Методы `GET`, `PUT` и `DELETE` обладают идемпотентностью, в то время как `POST` — нет.

## 2.1. Разбор запроса

```http
POST /api/users HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...
Content-Length: 58

{"name": "Иван", "email": "ivan@mail.com"}
```

1. **Метод:** `POST`. Применяется для генерации новых записей и передачи данных на сервер.
2. **Путь:** `/api/users`. Целевой эндпоинт, с помощью которого осуществляется работа с учетными записями пользователей.
3. **Версия:** `HTTP/1.1`.
4. **Content-Type:** `application/json`. Уведомляет сервер о том, что передаваемая полезная нагрузка оформлена в формате JSON.
5. **Authorization:** `Bearer...`. Заголовок авторизации, содержащий токен доступа. Позволяет серверу идентифицировать пользователя и проверить права на выполнение операции.
6. **Тело запроса:** строка с полезной нагрузкой `{"name": "Иван", "email": "ivan@mail.com"}`, отделенная от заголовков пустой строкой. Заголовок `Content-Length: 58` фиксирует точный объем этих данных в байтах.

## 2.2. Разбор ответа

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/users/42

{"id": 42, "name": "Иван", "email": "ivan@mail.com"}
```

1. **Статус 201:** `Created`. Сигнализирует об успешном создании нового ресурса на стороне сервера.
2. **Location:** `/api/users/42`. Ссылка-указатель на только что созданный объект, позволяющая незамедлительно обратиться к нему.
3. **Тело ответа:** содержит детальную информацию о созданном пользователе, включая присвоенный системный идентификатор (`id: 42`).

## 2.3. Составление запросов

### 1. Получить список всех товаров

```http
GET /api/products HTTP/1.1
Host: example.com
Accept: application/json
```
Метод `GET` предназначен исключительно для чтения информации и не производит никаких модификаций в системе.

### 2. Создать новый товар

```http
POST /api/products HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <токен>
Content-Length: <длина_тела>

{"name": "Ноутбук", "price": 50000}
```
Метод `POST` инициализирует добавление нового товарного позиционного элемента, передавая его параметры внутри тела запроса.

### 3. Удалить товар с id=7

```http
DELETE /api/products/7 HTTP/1.1
Host: example.com
Authorization: Bearer <токен>
```
Метод `DELETE` инициирует удаление конкретного объекта, идентификатор которого непосредственно прописан в пути запроса.

### 4. Обновить товар с id=3

```http
PUT /api/products/3 HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <токен>
Content-Length: <длина_тела>

{"name": "Ноутбук", "price": 45000}
```
Метод `PUT` осуществляет полную замену ресурса новыми данными. Если требуется скорректировать лишь отдельные параметры (например, цену), целесообразнее использовать метод `PATCH`:

```http
PATCH /api/products/3 HTTP/1.1
Host: example.com
Content-Type: application/json
Authorization: Bearer <токен>
Content-Length: <длина_тела>

{"price": 45000}
```
