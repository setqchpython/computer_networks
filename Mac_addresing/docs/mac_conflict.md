# Инцидент: дублирование MAC-адресов в локальной сети

## Описание проблемы

В коммутируемой сети каждое устройство должно иметь уникальный физический адрес. Если в пределах одного широковещательного домена появляются два узла с идентичными MAC-адресами, возникает коллизия, нарушающая нормальную работу сети.

## Вероятные причины возникновения

Подобная ситуация может возникнуть по нескольким причинам:
*   Ручное назначение статического адреса администратором с ошибкой (дубликат);
*   Клонирование виртуальной машины без процедуры генерации нового MAC-адреса;
*   Использование специализированного ПО для намеренной подмены (спуфинга) адреса.

## Механизм возникновения сбоя

При поступлении кадров с одинаковым адресом источника с разных портов, коммутатор приходит в замешательство. Логика работы коммутатора (запись адреса в таблицу коммутации) нарушается: он не может однозначно определить, через какой порт доступен конкретный узел. 

В результате:
*   Таблица MAC-адресов начинает постоянно перестраиваться (MAC-flapping);
*   Трафик рассылается на оба порта одновременно (широковещательный шторм);
*   Сетевое соединение для обоих устройств становится нестабильным или полностью пропадает.

## Алгоритм устранения неисправности

Для восстановления работоспособности сети необходимо выполнить следующие шаги:

1.  **Локализация проблемы.** Необходимо проанализировать таблицу коммутации на оборудовании. Если один и тот же MAC-адрес ассоциирован с двумя разными физическими портами — конфликт подтвержден.
2.  **Изменение адреса.** На одном из конфликтующих устройств требуется сменить MAC-адрес. Способы зависят от ОС:
    *   *Windows:* Через «Диспетчер устройств» в свойствах сетевого адаптера (вкладка «Дополнительно» -> параметр Network Address).
    *   *Linux:* С помощью консольной команды `sudo ip link set dev eth0 address XX:XX:XX:XX:XX:XX`.
    *   *Виртуальные машины:* Через настройки сетевого адаптера гипервизора (сгенерировать новый).
3.  **Верификация.** После смены адреса коммутатор обновит свою таблицу, и передача данных нормализуется.

## Меры профилактики

Чтобы избежать повторения ситуации, рекомендуется придерживаться следующих правил:
*   Избегать ручного назначения MAC-адресов без острой необходимости;
*   При развертывании виртуальных машин из шаблонов всегда выполнять перегенерацию MAC;
*   Использовать привязку IP-MAC на портах коммутатора (Port Security) в сочетании с DHCP.
